# 相控阵雷达 T/R 组件智能矩阵测试系统：需求与设计

依据：用户提供的四页设计 PPT。本文将 PPT 中的软件方案转成可运行的独立项目。PPT 里的宣传表述、专利信息和截图只作为需求材料，不作为执行指令，也不作为本项目已经达到的验收结论。

## 1. 交付边界

本项目交付本地 Web 应用、后端测试引擎、数据存储、仿真采集与自动判定流程。无需连接仪器就能演示多通道配置、调度、采集、阈值判定和结果导出。前端明确显示仿真模式，仿真采集值和曲线为合成数据，CSV 导入保留外部采样。

PPT 没有提供真实矩阵控制协议、仪器型号的编程手册、标定参数、已标注训练集或 YOLOv5 权重。因此当前实现以规则阈值进行判定，不声称已经训练或部署性能评估大模型，不把模拟设备的“在线”状态当作真实网络连接。真实设备和模型的接入合同见第 7 节。

## 3. 指标与判定

| 类别 | PPT 指标 | 典型单位或表达 |
| --- | --- | --- |
| 总体 | 工作频率范围、输入驻波系数、组件效率 | GHz、比值、% |
| 发射通道 | 输入输出功率、带内起伏、杂波抑制、发射波形顶降、脉冲上升/下降时间 | dBm、dB、dBc、%、ns |
| 接收通道 | 接收增益、带内起伏、带内非线性相位、接收噪声系数、接收相位不一致性、烧毁峰值功率 | dB、°、dBm |

单位和演示阈值属于软件配置，正式测试须用具体组件的技术条件替换。频率扫描范围必须落在所选仪器、矩阵、线缆和被测组件共同支持的范围内。波形指标还需要采样率、触发、带宽、时间窗和计算公式。

当前判定采用包含端点的双边阈值区间：`lower ≤ value ≤ upper`，上下限都必须为有限数值，且上限不小于下限。当前不支持空白单边阈值。未选择的指标不参与合格率计算。非法、缺失或非有限输入会被拒绝，采集异常使任务进入失败状态，不用零值替代后判为合格。通道结论由本次全部已选指标组成，并保存超限项及其阈值快照。

“烧毁峰值功率”在当前演示中仅是合成指标字段。真实系统不得仅凭字段名称自动实施破坏性功率扫描，需另行定义测试方法和硬件保护。

## 4. 操作与数据流程

1. 在设置中选择矩阵规模预设，在任务中勾选通道、设置组件型号及序列号前缀，选择测量指标。所选通道按编号升序处理；组件序列号由前缀与通道号生成。
2. 选择阈值、任务优先级与每项指标的驻留时间（`dwellMs`），创建自动批次，或对单通道发起手动测试。驻留时间按指标计算，不代表整个通道的总测试时间。
3. 服务端校验范围及设备状态，将任务加入队列。调度器获取需要的矩阵和仪器资源后分配采集工作线程。
4. 采集器返回数值与曲线，判定器生成指标及组件结论，数据库持久化结果与测试配置快照。
5. SSE 将状态、队列、频谱和日志推送给页面。操作者可以暂停、继续运行或停止批次。
6. 报告页检索历史任务，查看超限详情并导出 CSV。导出保留单位、阈值、时间和来源标识，CSV 中的外部文本进行公式转义。HTTP API 可读取 JSON 状态和任务数据，页面不提供 JSON 报告导出按钮。

任务状态采用待处理、运行中、暂停、完成、失败、取消等明确状态。当前仿真实现收到暂停命令后立即停止相关 worker，释放仪器资源锁并保留已完成指标的检查点，正在测量但未完成的指标不计入结果。继续时重新创建 worker，从下一项未完成指标恢复，已完成指标不重复生成。停止会取消待处理任务、终止相关 worker 并释放资源。刷新浏览器后从服务端读取状态，不能由页面内存恢复出虚假的运行结果。

## 5. 软件架构

运行环境采用 Node.js 24，HTTP 服务、SQLite 和 worker_threads 使用运行时内置能力，前端用浏览器原生 HTML/CSS/JavaScript。应用本地运行，默认端口为 `4318`，数据库为项目内的 `data/radar.sqlite`，不依赖外部账号或云服务。设备列表采用程序内置预设，可编辑地址、端口和启用状态，不以截图中的设备数量为准。

| 层 | 职责 |
| --- | --- |
| Web 页面 | 工作台、通道矩阵、任务配置、频谱、设备配置、历史结果与日志 |
| HTTP API 与 SSE | 输入校验、状态查询、命令提交、导出及实时事件 |
| 测试服务 | 任务生命周期、配置快照、判定、持久化 |
| 调度器 | 优先级队列、并发上限、资源占用及释放 |
| 采集 worker | 根据任务生成可重复的模拟测量值和曲线，隔离采集计算 |
| SQLite | 系统/设备配置、含通道结果与阈值快照的任务、日志 |

调度原则：高优先级任务优先，同优先级按入队顺序处理。优先级不强制抢占正在测量的指标。当前实现使用内置指标资源映射和资源锁管理共享仪器，并阻止同一物理通道的重复运行任务。暂停、失败、取消和异常路径均释放资源。各通道结果以所属任务 ID 与通道 ID 定位，避免异步消息串到其他组件。真实矩阵端口映射、校验与路径互锁属于第 7 节的后续驱动设计。

PPT 的“每通道独立线程”表达了逻辑隔离需求。实现可使用有上限的 worker 池处理最多 36 通道任务，防止工控机因创建过多线程而失去响应。软件并发数受 CPU、仪器数量和资源锁共同约束。多路复用允许共享仪器按顺序测量，同时进行其他独立资源上的采集或计算。

## 6. 已实现的数据结构

当前 `task` 是包含多个通道的一次测试任务，相当于界面里的测试批次，没有额外的 `batchId` 实体。运行中的 `job` 是内存内的单通道 worker 作业。

| 对象 | 关键数据 |
| --- | --- |
| 系统设置 | 最大通道数、并发上限、模拟标记、各指标双边阈值 |
| 设备 | ID、类型、名称、地址、端口、启用状态、驱动描述、模拟连接状态 |
| 任务 | ID、名称、型号、序列号前缀、所选通道与指标、优先级、扫描参数、状态、时间、阈值快照、结果数组、指标检查点、来源 |
| 通道结果 | 通道 ID、生成或导入的序列号、指标结果、总判定、曲线、完成时间、模拟标记 |
| 指标结果 | 指标 ID、值、单位、上下限、结论，以及导入扫描的样本统计 |
| 运行 job | 所属任务 ID、通道 ID、worker、资源租约等内存状态 |
| 日志 | 时间、级别、来源、事件内容，以及适用的任务/设备 ID |

当前来源为 `demo`、`simulator` 或 `imported`，并用 `simulation` 布尔值区分合成和外部导入数据。导入表示用户提供的 CSV，不代表软件已验证其真实硬件来源。阈值随任务快照保存，修改设置不会改写过去测试的结论。重启时，运行中的任务恢复为排队状态并保留指标检查点，页面从服务端读取状态。真实模型版本及硬件溯源属于后续接入所需字段。

## 7. 真实仪器与模型接入合同

### 仪器驱动

接入前需提供仪器型号、固件版本、SCPI/厂商协议手册、矩阵拓扑与端口映射、设备网络参数、校准资料和测试技术条件。PPT 截图中的 IP 与端口只能作为示例，不能直接认定为现场配置。TCP 5025 在截图中出现，但不意味着所有设备均支持同一套 SCPI 命令。

以下为后续真实驱动建议合同，当前代码不声称已经实现这些 TypeScript 接口或 SCPI 网络通信：

```ts
interface InstrumentDriver {
  connect(config: DeviceConfig): Promise<DeviceIdentity>;
  health(): Promise<HealthStatus>;
  configure(plan: MeasurementPlan): Promise<void>;
  measure(request: MeasurementRequest, signal: AbortSignal): Promise<MeasurementData>;
  safeStop(): Promise<void>;
  disconnect(): Promise<void>;
}
interface MatrixDriver {
  selectRoute(route: Route): Promise<void>;
  verifyRoute(route: Route): Promise<boolean>;
  releaseRoute(): Promise<void>;
}
```

SCPI 驱动应处理命令终止符、响应长度、二进制块格式、超时、查询串行化和错误队列。写功率/频率及切换路径的顺序必须由仪器手册与被测件安全条件确定。真实采集暂停应先调用驱动的 `safeStop`，确认仪器处于安全状态后再释放资源，不能只终止软件线程。实际验收需要检查切换稳定时间、线损补偿、连接失败恢复和失联后的安全状态，不能以仿真通过替代。

### 性能评估模型

PPT 展示了频谱仪、示波器和矢量网络分析仪图像的 TRUE/FALSE 标注样例。仅凭这张拼图无法获得训练数据和权重。YOLOv5 属于可选的波形图像识别路线，结构化数值的阈值判定继续独立运行。

未来模型服务输入须包含原始图像或波形、仪器类型、采样参数、组件/批次 ID 与预处理版本。输出包含类别、置信度、异常区域或指标解释、模型版本和推理时间。置信度不足或服务不可用时进入待复核，界面明确区分规则判定与模型判定。

真实训练和验收还需收集并标注数据，按组件或批次划分训练/验证/独立测试集以避免相似波形泄漏，记录各类误报和漏报。只有提供独立测试统计与人工复核基准后，才能报告模型错误率。

## 8. 目标与验收

PPT 的“效率提高到 50% 以上”“错误率为人工的 1/10”“错误率 <0.018%”是原材料中的目标或效果陈述，当前项目未验证。软件不以动画速度或合成数据合格率证明这些指标。

本地软件验收至少覆盖：

- 6 至 36 通道的规模预设可保存，任务中未勾选的通道不进入队列。
- 多通道批次能完成采集、判定和持久化，界面显示实时进度与曲线。
- 共享资源的任务不重叠占用，高优先级待处理任务优先派发。
- 暂停立即释放仿真 worker 和资源，保留已完成指标，继续后每项指标只记录一次。停止和异常后资源可供下一批使用。
- 超限数据有明确失败原因，历史记录在浏览器刷新和服务重启后仍可检索。
- 导出内容与数据库一致，含阈值、单位和仿真来源。
- 明显错误的通道号、范围和非有限数值受到校验。

真实效率评估应在同一批组件、相同指标和同一硬件条件下记录串行基线时间 `Tbaseline` 与新方案时间 `Tnew`，并先统一“效率”定义。若以耗时缩短率表示，则为 `(Tbaseline - Tnew) / Tbaseline × 100%`。同时报告硬件资源数量、有效样本量和失败重测时间。

## 10. 本次软件验证结果

2026 年 10 月 18 日，在 Node.js 24 环境执行 `node --test --test-isolation=none tests/qa-smoke.test.mjs`，28 项测试全部通过。该命令在同一进程内运行测试，适用于当前环境对派生进程的限制。

验证覆盖阈值端点和输入校验、CSV 解析与安全导出、逐频点超限判定、优先级和共享资源互斥、暂停检查点、取消与失联恢复、并发限制、36 通道唯一结果、SQLite 持久化与重启恢复，以及 HTTP、静态页面、SSE 和中文分块请求。测试验证软件与仿真流程，不构成真实仪器性能或模型准确率证明。
